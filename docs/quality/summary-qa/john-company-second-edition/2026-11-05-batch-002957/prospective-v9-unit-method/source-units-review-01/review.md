# Generic source-unit technical review

The helper preserves exact substrings of the supplied Python Unicode string for ordinary supported inputs. It is useful as a restricted-format extraction aid. It does **not** establish complete operative Markdown units, controlling headers, or governing context for arbitrary Markdown. The low-level table validator supplies materially weaker checks than the high-level extractor. Shared code was not changed. This review makes no factual QA verdict or adoption decision.

## Concrete findings

**F1 — Low-level table validation does not validate the controlling header.** `validate_table_unit` checks exact row text, its trimmed complete physical line, both outer pipe characters, and optional cell-count equality. The header is checked only against its own Python slice and cell count. It accepts (a) `| A | B |` cropped from the original `| A | B | C |` header for a two-cell row, (b) a distant unrelated `| X | Y |` line, (c) the data row itself as the header, and (d) a header with a negative start offset using Python negative slicing. With no header argument, a separator line is accepted as a row. Positive controls reject changed row text, cropped rows and mismatched header cell counts. A successful low-level call is not evidence of header completeness, locality, type or control.

**F2 — The high-level table extractor's structural guarantee is limited.** `table_units` selects the last separator before the target within consecutive pipe-starting lines and uses the preceding line as header. It correctly rejects an absent separator, a selected separator, mismatched selected header/separator/row counts, and reuse across a blank gap. However, `| A | B |`, separator, separator, data labels the second separator's preceding separator as the header. A malformed intervening `| broken` line is ignored while a later complete row is returned. It does not validate the entire intervening block or prove that the selected header controls the requested fact.

**F3 — The final outer pipe is not escape-aware.** Interior parsing correctly distinguishes odd and even backslash runs before a pipe. But `cells("| a | b \\|")` accepts the escaped final pipe as the required outer delimiter. It returns cells containing a dangling backslash. This cannot prove the promised complete, explicitly outer-delimited row. Reject escaped terminal boundary pipes or narrow the contract; optional outer delimiters in some Markdown dialects do not rescue the stated explicit-outer-pipe check.

**F4 — A nested item omits parent context.** The most deeply indented candidate wins. Selecting the child in `- Parent qualifier.\n  - Child detail.` returns only `- Child detail.`. Parent qualifiers, sibling exceptions, section conditions, table captions, definitions and cross-references are not retrieved. The tested parent selection retains nested items and indented continuation; a blank followed by a dedented parent continuation correctly ends a child. These successes do not make a child an independently operative rule. Manually inspect and include required parent/section/external context.

**F5 — Bounds are not validated before indexing/trimming.** `unit("abc", 0, 10)` raises `IndexError`, while `unit("abc ", -1, 3)` silently normalizes the invalid negative start to zero and returns `abc`. Some invalid offsets are correctly rejected by high-level functions, but the low-level `unit` contract is inconsistent. Validate integer types and `0 <= start < end <= len(text)` before indexing; then reject empty trimmed results. Apply explicit bounds to optional headers too. Malformed dictionaries/types can otherwise produce ordinary Python `KeyError`/`TypeError`; no complete input-schema validation is provided.

## Supported behavior and limitations

**S1 — Exactness within the supported subset.** The copied six tests and added probes demonstrate complete long selected table rows, selected header/separator/data column-count equality, cropped/changed row rejection, odd/even escaped interior pipes, emoji and combining marks before CRLF table rows, ordinary LF/CRLF blank-line paragraphs, ordered items, nested items and indented continuation. Every returned `start:end` uses Python Unicode code points and a half-open range in the supplied string. This says nothing about relevance, rule interpretation, case correctness or completeness of asked facts.

**L1 — Whitespace trimming is part of the contract.** `unit` strips all leading/trailing Python `isspace()` characters, including indentation, tabs, CR/LF, NBSP and em-space. Exact output is the trimmed source span, not the entire physical line including indentation/line ending. Internal text remains unchanged. An offset on a table row's trailing newline can select a row whose trimmed span excludes that offset. Select content offsets, document trimming explicitly, and do not claim retained indentation or byte-for-byte whole-line preservation.

**L2 — Tables require a restricted source format.** Both outer pipe characters are required, separators need at least three hyphens per cell with optional colon alignment, and target/header/separator must have matching parsed cell counts. Optional outer pipes are unsupported. A table-like block inside triple-backtick code is accepted; there is no fenced-code, blockquote, HTML or Markdown container awareness. Some dialects permit uneven rows, but this helper deliberately rejects selected count mismatch. Correctness therefore requires a source-format check independent of extraction. A source header with the right cell count can still be the wrong header for the fact.

**L3 — `paragraph_unit` is a blank-line chunk selector, not a Markdown paragraph parser.** The delimiter is LF, optional spaces/tabs/CR, LF. It can absorb a heading and following text, or an adjacent list without a blank line; `validate_text_unit` repeats this same behavior and accepts the result. CR-only blank lines are not recognized. `lines` uses `str.splitlines`, including Unicode line separators, while paragraph separation uses LF only; the two do not share a universal line model. Fences, setext headings, tables and containers are not parsed. Restrict use to verified plain prose separated by LF/CRLF blank lines, or use a parser with source positions.

**L4 — List parsing is also a restricted heuristic.** It recognizes space-indented unordered markers and decimal markers ending `.` or `)`, plus column-zero ATX headings as a terminator. It does not recognize tab indentation or indented/setext headings as structure and has no fenced-code state. A bullet-like line inside a valid indented fenced continuation is selected as a nested child, demonstrating a false structural unit. Indented ATX/setext headings can be swallowed. Markdown lazy continuation, loose lists, mixed containers, thematic breaks and other dialect details require source inspection; they are not generally guaranteed by these tests.

## Necessary usage checks and changes

For an unchanged helper, readers must first inspect the original source structure and establish that the chosen unit fits the supported subset. Use `table_units` rather than treating `validate_table_unit` alone as a header selector. For any supplied row/header, compare them with the high-level extraction, then separately verify an actual non-separator header, a valid intervening table block, explicit unescaped boundaries and surrounding containers. That comparison alone does not resolve F2 or semantic control. Use paragraph/list extractors only after checking structural boundaries and include required parent material explicitly. `validate_text_unit` is a consistency check against the same heuristic, not an independent Markdown validator.

To support stronger automated claims, upstream would need early bound checks, complete/local non-separator header validation, escape-aware outer delimiters, validated table blocks and either explicit restricted-grammar rejection or a Markdown parser preserving original positions. None of those changes were applied here. If preserving this helper unchanged is required, narrow the instructions to its measured guarantees and retain independent human/source checks rather than advertising arbitrary complete operative Markdown extraction.

Preserve the original text before calling the helper: decoding and universal-newline conversion can change offsets before extraction. Hash the frozen bytes and record decoding/newline handling; never normalize the working string after offsets are chosen. Python code points differ from UTF-8 bytes, UTF-16 indices and user-perceived graphemes. An exact span relative to a normalized string does not prove the offsets refer to the original file.

A full local unit can still omit external governing definitions or conditions. Fresh source-only readers must independently determine relevant units and necessary conclusions/calculations from their own source. Any later grading must independently assess every asked fact from the same entry; helper success must not substitute for that assessment or supply a case answer. The parent retains the adoption decision.
