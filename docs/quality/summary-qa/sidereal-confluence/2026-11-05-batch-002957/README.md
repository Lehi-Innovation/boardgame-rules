## Process and limits

Reader rules data are only a frozen summary and frozen questions. New readers have explicit fork-none context, actual Luna/high runtime records, complete bounded model-visible input delivery, independently selected operative evidence, and unchanged generic source extraction code. A correct attached quote cannot cure a contradictory direct claim or missing requested concrete result. All substantive fields of each original entry are graded; answers cannot borrow from another question. Formatting, duplicate excerpts and receipt/code-serialization diagnostics remain separate from factual scores.

Fresh independent Sol/high reviewers grade disjoint whole-entry bundles against every actually asked fact. Source-only auditors see the exact summary and actual authorities/provenance, without questions, keys, maps, reader answers, grades or earlier findings. Coverage reviewers see sources and current questions/key/scope/map, without the summary or reader results.

This is a known fixed-set, tool-assisted regression with instruction/context isolation, not OS file isolation, held-out model accuracy or proof of every conceivable scenario. Ordinary printed card quantities, cosmetic numeric substitutions, optional variants and unsupported hypotheticals do not create a separate question quota. Runtime evidence contains minimal identity, parent/task, requested/observed model/effort/fork, ordinals and opaque hashes; original logs remain untouched and private instruction/account objects are not copied.

The coordinator owns registration and verification stamping. Any summary-byte change, including stamping, requires the authorized exact-byte reader/audit gate before final completion.
